6. CONFLICT CASE: CONCURRENT SKU COLLISION (TABLE IV VERIFICATION)
--------------------------------------------------------------------------------
Direct empirical validation of non-I-confluent invariants under partition.

Experimental Scenario:
- Nodes nA and nB partitioned from one another.
- Concurrent insertion of identical unique SKU:
  - nA commits: INSERT INTO items (sku, name, price, category_id)
                VALUES ('SKU-PRO-400', 'Industrial Sensor A', 89.99, 1)
                Clock: V_A = <nA: 51, nB: 0, nC: 0, nD: 0>
  - nB commits: INSERT INTO items (sku, name, price, category_id)
                VALUES ('SKU-PRO-400', 'Industrial Sensor B', 94.50, 1)
                Clock: V_B = <nA: 0, nB: 51, nC: 0, nD: 0> (V_A || V_B)
- Both transactions pass local validation and commit to local SQLite WAL.
- Reconnection triggered; envelopes exchange over GossipSub.

Empirical Outcome:
- Node nA receives nB's envelope:
  - SQLite raises: "UNIQUE constraint failed: items.sku"
  - Replay engine catches exception, logs rejection in `_mesh_conflicts`.
  - Node nA retains its local record ("Industrial Sensor A").
- Node nB receives nA's envelope:
  - SQLite raises: "UNIQUE constraint failed: items.sku"
  - Replay engine catches exception, logs rejection in `_mesh_conflicts`.
  - Node nB retains its local record ("Industrial Sensor B").
- Nodes nC and nD:
  - Commit whichever envelope arrives first via gossip routing.
  - Reject the second arrival due to SQLite unique constraint failure.
- Divergence Metric:
  - Temporary divergence observed exactly as documented in Table IV!
  - Zero database crash or unhandled exception.
  - Proves the boundary of I-confluence and motivates future CRDT merge algebras.
